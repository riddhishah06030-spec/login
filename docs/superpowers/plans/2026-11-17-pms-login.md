# PMS Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Next.js login screen with username, password, pharmacy location, and §6 role-mapped demo accounts, then run the app.

**Architecture:** App Router pages for `/login` and `/dashboard`. Client-side mock auth validates against a static demo user table and stores session in `sessionStorage`. Split-panel clinical UI with CSS Modules.

**Tech Stack:** Next.js (latest App Router), TypeScript, CSS Modules (no Tailwind)

## Global Constraints

- UI-only mock auth — no NextAuth, no database
- Demo password for all seed users: `demo1234`
- Roles must match Requirement §6 list
- Brand: Canadian Pharmacy OS (hero on login left panel)
- Cool teal/slate palette; avoid purple SaaS look
